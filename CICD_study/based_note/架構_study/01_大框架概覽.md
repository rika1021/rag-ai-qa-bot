# CI/CD 大框架概覽

> 學習目標：從零開始理解 CI/CD，對應緯穎 Server 韌體開發流程

---

## 一、CI/CD 是什麼？

**一句話理解：**
把「寫程式」→「上線」這段路，自動化、快速化、有品質保證地跑完。

---

## 二、CI / CD 分別是什麼？

```
開發者 push 程式碼
        ↓
  ┌─────────────┐
  │  CI（持續整合）│  ← 自動跑測試、確認程式沒壞
  └─────────────┘
        ↓
  ┌─────────────┐
  │  CD（持續交付/部署）│  ← 自動打包、部署到目標環境
  └─────────────┘
        ↓
    產品上線 / 韌體燒錄 / 測試機台跑測
```

| 縮寫 | 全名 | 白話意思 |
|------|------|----------|
| CI   | Continuous Integration  | 每次有人改程式，就自動測試「有沒有壞掉」 |
| CD   | Continuous Delivery     | 測試沒壞，就自動把成品「準備好」可以交付 |
| CD   | Continuous Deployment   | 更進一步，直接「自動部署」到生產環境    |

## 三、整個流程的大地圖

```
┌──────────────────────────────────────────────────────────────┐
│                        CI/CD Pipeline                        │
│                                                              │
│  [1. 原始碼]  →  [2. 觸發]  →  [3. 建置]  →  [4. 測試]      │
│                                                              │
│       →  [5. 打包/容器化]  →  [6. 部署]  →  [7. 驗收測試]   │
└──────────────────────────────────────────────────────────────┘
```

### 每個階段說明

| 階段 | 動作 | 對應工具範例 |
|------|------|-------------|
| 1. 原始碼管理   | 工程師把程式碼存到版本控制系統         | Git, Gerrit               |
| 2. 觸發         | 有人 push/merge，自動啟動流程          | GitHub Webhook, GitLab CI |
| 3. 建置 (Build) | 把原始碼編譯成可執行檔                 | Makefile, CMake, Gradle   |
| 4. 測試 (Test)  | 自動跑單元測試、整合測試               | pytest, JUnit, Robot Framework |
| 5. 打包         | 把程式包成可移植的格式                 | Docker image, RPM/DEB     |
| 6. 部署 (Deploy)| 把成品送到目標機器上                   | Jenkins, Ansible, Kubernetes |
| 7. 驗收測試     | 在真實環境驗證功能                     | 自動化測試腳本、硬體 HIL 測試 |

## 四、緯穎（Server 硬體廠）的 CI/CD 特殊性

```
純軟體公司：  程式碼 → 部署到雲端 Server → 完成
緯穎這類公司：程式碼 → 燒錄到實體硬體 → 跑硬體測試 → 完成
```

### 緯穎可能的 Pipeline 大框架

```
Gerrit/GitHub                Jenkins                   Test Farm
(程式碼審查)    ──觸發──▶   (自動化調度)   ──分發──▶  (實體機台)
      │                         │                         │
   BMC/BIOS              Build BIOS/BMC               燒錄韌體
   韌體程式碼              firmware image            自動跑 LLT/HLT
                                                    (Lab Level Test)
```

### 關鍵術語

| 術語 | 意思 |
|------|------|
| BMC       | 主板管理控制器，控制伺服器電源/監控/遠端管理的小韌體 |
| BIOS/UEFI | 開機韌體                                           |
| LLT       | Low Level Test，底層硬體測試                        |
| HIL       | Hardware-in-the-Loop，用真實硬體做測試              |
| Test Farm | 一堆測試用實體機台的機房                            |

## 五、主要工具生態系

```
版本控制層：  Git ──── GitHub / GitLab / Gerrit
                              │
自動化調度層：         Jenkins / GitLab CI / GitHub Actions
                              │
容器化層：                  Docker / Podman
                              │
部署/配置層：          Ansible / Kubernetes / Helm
                              │
測試層：           pytest / Robot Framework / 自製測試框架
```
